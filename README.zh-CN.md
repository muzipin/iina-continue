# Continue

[English](README.md)

## 项目介绍

Continue 可以让 IINA 正在播放的本地媒体在同一局域网内续播到另一个设备的浏览器，并在返回 IINA 时从最新播放位置继续。它是一款本地优先的 IINA 插件，不需要账号、手机 App、云端中继，也不会在运行时下载组件。

## 功能介绍

- 在 IINA 与另一个设备之间续播，同一时间只允许一端播放。
- 使用浏览器原生播放器完成播放、暂停和进度调整。
- 即使另一个设备仍在播放，也能暂停该设备并从最新确认位置返回 IINA。
- 在媒体处理路径支持时，带上 IINA 当前选中的文本字幕轨道。
- 提供自动、原始、1080p 和 720p 画质；兼容文件直接传输，其余受支持文件由随包的最小化 FFmpeg 处理。
- 使用密码学随机地址保护临时连接，并绑定第一台连接的设备。

## 安装

Continue 需要 Apple 芯片 Mac（Intel 芯片 Mac 暂不支持）、macOS 12 或更高版本、IINA 1.4.0 或更高版本，以及供两台设备共同连接的可信 IPv4 局域网。

### 在线安装

1. 打开 IINA → 设置 → 插件。
2. 选择“从 GitHub 安装”。
3. 输入 `muzipin/iina-continue` 并确认安装。

### 本地安装

1. 从对应的 GitHub Release 下载 `iina-continue-v<version>-arm64.iinaplgz` 和 `SHA256SUMS`。
2. 可在终端中校验安装包：

   ```sh
   shasum -a 256 -c SHA256SUMS
   ```

3. 打开 IINA → 设置 → 插件 → 安装插件，选中已下载的 `.iinaplgz` 文件并确认安装。

安装包已包含运行所需的全部组件，Continue 运行时不会再下载软件。

IINA 1.5.0 正式发布后，Continue 将使用其本地化插件元数据跟随 IINA 的语言。IINA 1.4.x 的插件管理器会显示英文简介，运行界面则跟随系统/WebView 语言。

## 构建与测试

构建过程会在当前工作空间的 `build/` 目录中生成中间产物，并在 `dist/v<version>/` 中生成可安装插件、源码再分发所需的固定版本 FFmpeg 源码归档，以及覆盖这两个文件的 `SHA256SUMS`。这两个目录均由 Git 忽略。

```sh
make test
make all
```

构建需要兼容的 Apple silicon macOS 环境、Go 1.25.x、Node.js 18 或更高版本、macOS 命令行构建工具，以及在尚未缓存固定版本 FFmpeg 源码时可用的网络连接。更高版本的 Go 可能提高所生成 helper 的 macOS 最低版本，因此构建会拒绝不支持 macOS 12 的 helper。

`make all` 会运行 Go 和 JavaScript 测试，构建最小化的 arm64 LGPL FFmpeg，完成插件打包，并验证架构、最低系统版本、签名、动态依赖、FFmpeg 配置、包内容、校验值和 helper 自检。

发布新版本时，需要同步更新 `Info.json` 中面向用户的 `version`，并将用于 IINA 在线更新检查的整数 `ghVersion` 递增。

源码结构：

- `Info.json`：插件元数据与在线更新版本
- `plugin/`：插件运行源码、侧栏界面和 JavaScript 测试
- `helper/`：本地 Go 服务、另一个设备的播放页和 Go 测试
- `scripts/`：构建、打包和验证脚本
- `licenses/`：依赖源码与许可证信息

## 使用说明

1. 在 IINA 中播放一个受支持的本地文件。
2. 打开 Continue 侧栏，选择播放画质并点击“开始续播”。
3. 用另一个设备扫描二维码，在打开的浏览器页面中点击播放即可开始续播。
4. 在 IINA 中点击播放，即可同步播放进度并返回；再次点击另一个设备的浏览器页面中的播放按钮时，即可同步 IINA 的播放进度并续播。
5. 使用完毕后，可在任一设备点击“结束续播”，即可立即结束续播服务。

任何时候只会有一个播放器处于活动状态。返回 IINA 时，Continue 会先暂停另一个设备，再让 IINA 跳转到最新确认位置并继续播放。

## 使用限制

下表只说明大的支持范围，不代表对每一种封装、编解码、字幕、浏览器或网络组合做出保证。

| 范围 | v0.1.x 支持情况 |
| --- | --- |
| Mac | 仅支持 Apple 芯片，暂不支持 Intel Mac |
| 内容 | 只支持本地普通媒体文件；不支持网络地址、光盘、DRM 内容和播放列表 |
| 播放 | 一台 Mac 与同一可信 IPv4 局域网内的一台浏览器设备 |
| 媒体处理 | 兼容流可直接传输或重封装；部分不兼容流会使用硬件视频转码或 AAC 音频转码 |
| 字幕 | 媒体转换成功时支持当前选中的文本字幕；不支持图片字幕 |
| 视频范围 | 不提供 HDR 转 SDR，也不提供云端中继 |

不同浏览器和路由器的行为可能存在差异。对于重要文件，请先在实际设备上测试后再使用。

## 隐私和安全

Continue 不使用云服务，运行时也不会向互联网发起请求。媒体只会在 Mac 与第一台打开临时访问地址的设备之间传输。helper 为当前局域网会话提供服务，需要控制播放器的请求则限制在 Mac 的回环接口。

请将二维码及其中的地址视为临时访问凭证，只在可信局域网中使用，不要分享仍然有效的地址，并在不再使用时结束续播服务（当前默认的单次续播服务的有效时间为最长4小时，到期后自动结束会话）。

发现安全问题时，请通过 GitHub 仓库的安全公告功能私下报告，不要创建公开 Issue。报告中请说明受影响版本、影响范围和最小复现步骤，但不要附加私人媒体或仍然有效的访问地址。

## 贡献指南

请将修改保持在当前的本地优先范围内，除非确有必要，不要新增运行时依赖。提交 Pull Request 前：

1. 运行 `make test`。
2. 涉及发布的修改需在 Apple 芯片 Mac 上运行 `make all`。
3. 说明用户可见的变化，并更新对应测试。
4. 确认提交中不包含媒体文件、构建产物、访问凭证、仍然有效的访问地址或与本机绑定的路径。

提交缺陷报告时，请提供 IINA 和 macOS 版本、Mac 型号、媒体封装与编解码信息、字幕类型、播放画质和完整复现步骤。请勿附加受版权保护的媒体。
